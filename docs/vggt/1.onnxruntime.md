# ONNX Runtime

!!! danger "Previous statement was incorrect"
    The earlier version of this page claimed that exporting VGGT to ONNX is straightforward. This is misleading — **converting the model format is easy, but getting correct GPU inference results is the difficult part**.

## CPU Inference

ONNX Runtime works correctly on **CPU** for VGGT (and SmolVLM). If CPU inference is sufficient, ONNX is a viable option.

## GPU Inference — Not Recommended

### Windows (DirectML)

DirectML can execute the ONNX model on GPU, but:

- Changing input dimensions (e.g. from 2 images to 3) requires **manual graph layer adjustments**
- No automated tooling handles this — each input configuration needs custom work
- Efficiency is poor compared to PyTorch

### Linux (MIGraphX)

MIGraphX **compiles ONNX models into a static executable** before execution. This introduces two critical problems:

1. **Missing operator support** — MIGraphX does not support all operators required by this model on this device
2. **Static compilation** — every model change (even different image counts) requires recompilation. Smaller dimensions cause performance loss from suboptimal compilation; larger dimensions may fail to produce valid output

## Verdict

ONNX Runtime with GPU is **not recommended** for VGGT. Use **PyTorch** instead, which handles variable inputs correctly and efficiently.
